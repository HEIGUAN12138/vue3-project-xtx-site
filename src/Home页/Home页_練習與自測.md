# Home 页 · 练习与自测

> 题量：是非 10 / 选择 10 / 配对 8 / 情境 3 / 代码阅读 3 / 延伸思考 2。答案紧跟各区块。

## 一、是非题（10 题）

1. 首页采用「一个楼层一个接口」，是为了让单块失败不影响其他楼层。
2. `Promise.all` 中任何一个请求 reject，整体就会 reject。
3. `el-carousel` 会根据内部图片的高度自动撑开容器。
4. `img` 默认是块级元素，所以不会出现底部白边。
5. 面板组件用 props 传「类型」比用插槽传结构更抗变化。
6. `v-lazy` 指令在图片首次进入视口后应调用 `stop()`。
7. 指令的 `unmounted` 钩子可以用来兜底清理没有触发的观察器。
8. 给 `<img>` 先设一张占位图再替换，能减少总请求数。
9. `flex: none` 用在横向滚动的图标项上，可以防止它们被压缩变形。
10. 商品卡片内置「加入购物车」按钮属于纯组件能力问题，与产品决策无关。

### 答案解析

1. **对**。楼层独立成块，单块失败可以展示「该楼层暂无内容」，不至于整页空白。
2. **对**。这是 `Promise.all` 的短路语义，需要局部降级时改用 `Promise.allSettled`。
3. **错**。`el-carousel` 不会自动撑高，必须显式给 `height`，否则会塌成一条缝。
4. **错**。`img` 是行内替换元素，基线之下会留出几像素空隙，需 `display: block`。
5. **错**。用 props 传「类型」会把差异堆成条件分支，差异增长时代价反超收益；插槽把结构差异留在调用方。
6. **对**。不 stop 的话，每次交叉状态变化都会重新赋值，表现为图片闪烁、日志刷屏。
7. **对**。图片一直没进视口就离开页面时，观察器仍在，需要在卸载时清掉。
8. **错**。占位图本身也要下载，反而多一次请求；更好的做法是先不设 `src` 或用极小的 base64。
9. **对**。flex 子项默认 `flex-shrink: 1`，一行放不下时会被压扁。
10. **错**。「什么时候允许加购」是产品决策，不属于组件能力的范畴。

## 二、选择题（10 题）

1. 首页三个楼层接口并发发出，首屏耗时取决于？
   A. 三者之和　B. 最慢的那一个　C. 最快的那一个　D. 与并发无关

2. 希望「某个楼层接口挂了，其他楼层照常显示」，应改用？
   A. `Promise.race`　B. `Promise.all`　C. `Promise.allSettled`　D. 串行 `await`

3. 首页第一屏被吸顶导航盖住一截，最直接的修法是？
   A. 给 `body` 加 `overflow: hidden`　B. 内容区加 `padding-top: var(--header-height)`　C. 把导航改成 `position: static`　D. 给 `.home` 加 `z-index`

4. `el-carousel` 显示成一条缝，原因是？
   A. 缺少 `height`　B. 缺少 `interval`　C. 缺少 `arrow`　D. 缺少 `autoplay`

5. 运营图尺寸不一致时不想让人脸变形，应给图片设？
   A. `object-fit: fill`　B. `object-fit: cover`　C. `height: auto`　D. `transform: scale()`

6. 首页四个楼层结构相同、内容结构不同，面板组件最合适的传参方式是？
   A. 全部用 props 传数组　B. 全部用插槽　C. 标题用 props、内容用插槽　D. 用 `provide/inject`

7. 判断一个组件该进 `src/components/` 还是跟随页面，依据是？
   A. 文件行数　B. 被几个页面使用　C. 是否有插槽　D. 是否需要样式

8. 懒加载图片一闪一闪反复赋值，最可能缺的是？
   A. 节流　B. 首次进入视口后的 `stop()`　C. `loading="lazy"`　D. 占位图

9. 横排图标列表防止图标被挤扁，应给子项加？
   A. `flex: 1`　B. `flex: none`　C. `width: 100%`　D. `min-width: 0`

10. 后端 `price` 可能返回 `199` 也可能返回 `199.00`，统一显示的做法是？
    A. 要求后端统一格式　B. 在组件内 `Number(price).toFixed(2)`　C. 用 CSS 补零　D. 用 `v-if` 判断

### 答案解析

1. **B**。并发时总时间等于最慢的那个，串行才是相加。
2. **C**。`allSettled` 等所有请求结束，无论成败。
3. **B**。导航吸顶仍占位，内容必须留出等高通道，且用变量保证两者同源。
4. **A**。轮播组件不根据内容撑高。
5. **B**。`cover` 保持比例、裁掉溢出部分。
6. **C**。框子统一（props），货怎么摆交给调用方（插槽）。
7. **B**。复用范围决定归属。
8. **B**。观察器未停止，每次交叉状态变化都会重新赋值。
9. **B**。`flex: none` 同时把 `grow`/`shrink`/`basis` 复位，避免压缩。
10. **B**。格式化属于展示层职责，不应依赖后端保证。

## 四、情境分析（3 题）

### 情境 1：首页一片空白，只有轮播图区域

上线当天发现首页只渲染出轮播，下面两个楼层全空。Network 面板显示 `/home/new` 返回 500，`/home/hot` 正常返回 200。

**问**：为什么一个接口失败会导致两个楼层都不显示？怎么改？

**答**：代码用的是 `Promise.all([...])`，它在任意一个 reject 时就整体 reject，`await` 之后的赋值语句全部跳过，于是三个楼层的数据都没写进 store。修法二选一：改成 `Promise.allSettled`，或让每个请求自己 `catch` 后返回兜底值，实现「局部降级」。

### 情境 2：轮播图高度正常，但图片上下各有一条白线

运营换了批图之后，轮播区域出现上下白边，图片本身没变形。

**问**：定位方向是什么？

**答**：先看图片是否被拉伸变形——没变形说明 `object-fit` 生效。白边来自 `img` 的基线间隙，说明漏了 `display: block`。另外要确认容器高度与图片高度是否一致，若图片是 `height: 100%` 而父元素没有确定高度，也会出现留白。

### 情境 3：滚动页面时图片疯狂闪

首页商品图用了 `v-lazy`，用户上下滚动时图片反复消失再出现，控制台每滚一次就打一条日志。

**问**：原因与修法。

**答**：观察器在首次交叉后没有 `stop()`，之后每次进出视口都会重新执行赋值逻辑。修法是在命中 `isIntersecting` 后立刻 `stop()`，并把 `stop` 存到元素上，在 `unmounted` 里兜底调用一次。

## 五、代码阅读（3 题）

### 题 1

```js
onMounted(async () => {
  const [a, b, c] = await Promise.allSettled([
    getBannerAPI(), getNewAPI(), getHotAPI(),
  ])
  console.log(a.status, b.status, c.status)
})
```

**问**：`a.status` 可能取到哪些值？如果想让失败的楼层显示「暂无内容」，还需要做什么？

**答**：`fulfilled` 或 `rejected`。`allSettled` 只保证不抛错，不负责挑数据：需要逐个判断 `status === 'fulfilled'` 再取 `value.result`，`rejected` 的分支把列表置空并显示降级文案。

### 题 2

```js
export const lazy = {
  mounted(el, binding) {
    const { stop } = useIntersectionObserver(el, ([entry]) => {
      if (!entry.isIntersecting) return
      el.src = binding.value
    })
  },
}
```

**问**：这段代码与本章的版本差在哪里？会造成什么现象？

**答**：少了 `stop()` 与 `unmounted` 兜底，也没把 `stop` 存到元素上。现象是滚动过程中反复赋值、图片闪烁；若图片一直没进视口就离开页面，观察器泄漏。补法是首次命中后 `stop()`，`el._stopLazy = stop`，并在 `unmounted` 中清理。

### 题 3

```html
<HomePanel title="人气推荐" sub="人气爆款">
  <ul class="goods-list">
    <li v-for="g in hotList" :key="g.id">{{ g.name }}</li>
  </ul>
</HomePanel>
```

**问**：这个用法体现了哪种封装取舍？如果改成 `<HomePanel type="hot" :list="hotList" />` 会有什么后果？

**答**：体现「标题用 props、内容用插槽」——组件只管框子，调用方决定内容结构。改成传 `type` 加数组后，`HomePanel` 内部要按 `type` 写分支决定「显示价格还是只显示名字」，楼层一多 props 会膨胀，改一处样式会波及另一处。

## 六、延伸思考（2 题）

1. 首页楼层数量从 4 个增加到 12 个，每个楼层都写一遍 `ref` + `onMounted` + `try/catch`。请设计一个 `useFloor` 组合式函数，并说明哪些东西**不该**抽进去。

   **思路**：抽「取数、loading、错误状态、卸载前忽略写入」这几件共性的事，签名收敛成 `useFloor(fetcher, options)`。不该抽的是「接口地址、参数、字段映射、渲染结构」——一旦把它们塞进去，函数会退化成一张配置表，读代码要先查配置才能知道发生了什么。判断标准是：抽出来之后调用处是否变得更容易读。

2. 如果产品要求「首页首屏只加载可见楼层的图片，其余楼层滚动到位再请求接口」，与本章的「进入页面就并发请求三个楼层」相比，取舍是什么？

   **思路**：后者首屏数据全，用户往下滑不会有等待感，但首屏请求多、带宽竞争激烈；前者首屏更轻、LCP 更容易达标，但下滑时会出现「楼层空白 → 加载中 → 出现」的抖动，需要骨架屏弥补。真实项目里常混用：首屏两三个楼层直接请求，更靠下的楼层用 `IntersectionObserver` 触发懒请求；同时要保证「同一楼层只请求一次」，避免来回滚动反复触发。
