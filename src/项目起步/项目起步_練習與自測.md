## 一、是非题（10 题）

1. `create-vue` 生成的项目里，页面级组件应放在 `src/components/`。
2. 路径别名只需要在 `vite.config.js` 里配一次就能同时满足运行与编辑器跳转。
3. `jsconfig.json` 的 `paths` 是相对 `baseUrl` 解析的。
4. `unplugin-vue-components` 能处理 `ElMessage` 这类函数式 API 的自动导入。
5. 配置 `unplugin-auto-import` 之后，必须重启 dev server 才会生效。
6. CSS 变量方案既能改颜色，也能改组件圆角和间距。
7. SCSS 的 `@forward` 可以写在文件任意位置，只要变量在被引用之前出现即可。
8. 响应拦截器里返回 `res` 还是 `res.data` 属于个人偏好，不同接口可以不同。
9. 页面级路由组件用 `() => import()` 可以减小首屏包体积。
10. `public/` 下的图片会被 Vite 加上 hash 文件名。

### 答案解析

1. **错**。`components/` 放全局可复用组件，页面级组件放 `views/`。
2. **错**。编辑器靠 `jsconfig.json`/`tsconfig.json`，运行靠 `vite.config.js`，两边都要配。
3. **对**。所以 `baseUrl` 不能省。
4. **错**。函数式 API 需要 `unplugin-auto-import`；`unplugin-vue-components` 只处理模板标签。
5. **对**。插件在启动时读配置，改完必须重启。
6. **错**。CSS 变量只能覆盖已暴露的令牌，多数尺寸类需要 SCSS 变量在编译期替换。
7. **错**。Sass 要求 `@use`/`@forward` 位于文件最前面。
8. **错**。必须全项目统一，否则每处调用都要确认拆了几层。
9. **对**。这是路由懒加载的直接收益。
10. **错**。`public/` 原样拷贝、路径固定，不带 hash；`assets/` 才带 hash。

10. 想让「登录后回到原页面」，路由守卫里必须携带？

### 答案解析

1. **B**。红线是语言服务不认别名。
2. **B**。模板标签与函数式 API 由两个插件分别处理。
3. **B**。Sass 规定 `@use`/`@forward` 必须在最前。
4. **B**。后一个配置会覆盖前一个，两行 `@use` 必须写进同一个字符串。
5. **B**。`apis` 只拼参数、透传结果，不做二次解构。
6. **B**。401 是响应状态，统一在响应拦截器处理。
7. **B**。空路径即默认子路由。
8. **A**。Vue Router 按声明顺序匹配，静态段要写在动态段之前。
9. **B**。固定 URL、原样拷贝是 `public` 的判断依据。
10. **B**。`redirect` 保存原本要去的地址。

## 四、情境分析（3 题）

### 情境 1：改完配置全项目报「找不到模块」

某同学把 `@` 别名只配在 `jsconfig.json` 里，编辑器跳转正常，但 `npm run dev` 报 `Failed to resolve import "@/apis/home"`。

**问**：根因与修法。

**答**：`jsconfig.json` 只服务于编辑器的语言服务，真正解析 import 的是 Vite。需要在 `vite.config.js` 里补 `resolve.alias`，用 `fileURLToPath(new URL('./src', import.meta.url))` 指向 `src`。改完重启 dev server。

### 情境 2：主色改了，组件里其他地方还是蓝的

某同学在 `:root` 里写了 `--el-color-primary: #ff6b00`，按钮变橙了，但鼠标悬停时的浅橙、禁用态的灰橙仍然是蓝色。

**问**：为什么？怎么彻底解决？

**答**：Element Plus 的悬停色、禁用色是由主色按比例混合生成的（`--el-color-primary-light-3` 等），CSS 变量只覆盖了 `--el-color-primary` 本身，没有改这些衍生变量。彻底解决要用 SCSS 变量方案：`@forward ... with ($colors: ('primary': ('base': #ff6b00)))`，让编译期生成全部衍生色。

### 情境 3：登录后被踢回首页

用户点「结算」→ 守卫拦到登录页 → 登录成功跳回 `/` 而不是购物车。

**问**：哪里出了问题？给出修法。

**答**：守卫重定向时没有带 `redirect` 参数，登录页也就无从知道该回哪。修法：`return { path: '/login', query: { redirect: to.fullPath } }`，登录成功后 `router.replace(route.query.redirect || '/')`。

## 五、代码阅读（3 题）

### 题 1

```js
export default defineConfig({
  css: {
    preprocessorOptions: {
      scss: { additionalData: `@use "@/styles/var.scss" as *;` },
    },
  },
})
```

**问**：如果还要加主题定制文件 `element/index.scss`，应该怎么改？为什么不写成两个 `additionalData`？

**答**：合并成一行：`` additionalData: `@use "@/styles/element/index.scss" as *;\n@use "@/styles/var.scss" as *;` ``。写成两个键会互相覆盖，只有后一个生效。

### 题 2

```js
instance.interceptors.response.use(
  (res) => {
    if (res.data.code === 1) return res.data
    ElMessage.error(res.data.msg)
    return Promise.reject(res.data)
  }
)
```

**问**：这里为什么不能只判断 HTTP 状态码？`return Promise.reject` 的作用是什么？

**答**：小兔鲜的接口即使业务失败也返回 HTTP 200，错误码在响应体里，只看状态码会把失败当成功。`return Promise.reject` 让调用处的 `await` 进入 `catch`，否则调用方会拿到 `undefined` 继续往下走。

### 题 3

```js
routes: [
  { path: '/detail/:id', component: Detail },
  { path: '/detail/create', component: DetailCreate },
]
```

**问**：访问 `/detail/create` 会渲染哪个组件？怎么改？

**答**：会渲染 `Detail` 并把 `id` 设为 `'create'`，因为动态段在前会先匹配。把静态路径 `'/detail/create'` 移到前面即可。

## 六、延伸思考（2 题）

1. 「全量引入组件库只多 200KB，值得为此多配两个插件吗？」请从首屏性能与维护成本的权衡角度回答，并给出一个「不值得」的场景。

   **思路**：对 C 端电商首页，200KB 直接体现在首屏时间上，尤其在弱网下；两个插件是一次性成本。反例是内部后台系统，用户在内网、首屏性能不敏感，且团队新人多，自动导入带来的「组件来源不可见」反而是负担，此时全量引入更划算。

2. 请求层「统一返回 `res.data`」会让调用处失去对响应头、状态码的访问能力。什么情况下这个简化会变成障碍？

   **思路**：需要读取 `Content-Disposition` 下载文件、需要根据 `status` 区分 200 与 204、需要读取分页信息放在响应头里的接口。此时应保留一个「原始响应」的出口（例如另建 `requestRaw` 实例），而不是在统一封装里破例——破例会蔓延成「有的地方能拿到有的地方拿不到」。
