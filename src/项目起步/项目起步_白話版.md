# 项目起步

> 这一章是把毛坯房装成能住人的样子：水电（别名、请求）、门窗（路由）、家具（组件库）一样不能少。

## 一、脚手架与目录：create-vue 生成了什么

装修队交房时会给你一套样板间：沙发摆好了、画挂上了、厨房还放了假水果。`create-vue` 就是那个装修队，`npm create vue@latest` 敲完，一个能跑的 Vue 项目就出现在你面前，里面还带着几个示例页面。

但样板间不能直接住。那些 `HelloWorld.vue`、`TheWelcome.vue` 是给你看「大概长这样」的，留着它们，你就分不清哪个文件是自己写的。所以第一件事是把样板家具全搬走，只留承重墙：`vite.config.js`（水电图纸）、`jsconfig.json`（门牌对照表）、`package.json`（家当清单）、`index.html`（大门）。

房间怎么分区？一个简单原则：按「干什么」分，不按「什么东西」分。新手爱建一个「放 JS 的抽屉」、一个「放 CSS 的抽屉」，结果做一个功能要在三个抽屉之间来回翻。正确的分法是「商品相关的一间房」（接口在一个文件、页面在一个文件夹），做完一个功能就能关门走人。

还有一点：`src/apis/` 这个目录脚手架不会给你，是自己建的。它的作用是把「去哪个地址拿数据」这件事单独关起来，将来接口换了，只开这一扇门就行。

## 二、路径别名：jsconfig.json 与 vite.config.js 的双份配置

项目一大，引入文件就会变成 `../../../apis/goods`。数点号数到眼花，哪天把文件挪个位置，一屋子引用全断。别名就是给 `src` 起个外号叫 `@`，以后写 `@/apis/goods`，不管文件挪到哪都能找到。

这里有个所有人都绊过一次的坑：为什么配了别名，编辑器还是一堆红线？

打个比方。你家地址要登记在两个地方：一个是**邮局**（Vite），它负责真正把信送到；一个是**小区门卫的通讯录**（编辑器里的语言服务），它负责让你在门口就能查到「这户在哪」。你只告诉邮局，信能送到，但门卫查不到，你在编辑器里点「跳转到定义」就没反应、还会画红线。你只告诉门卫，门卫查得到，但邮局不知道往哪送，一运行就报「找不到模块」。

所以别名永远要配两遍：`vite.config.js` 里配 `resolve.alias` 给邮局，`jsconfig.json` 里配 `paths` 给门卫。改完之后，门卫那边还得「重启一下大脑」（命令面板里重启 TS 服务）才会认新地址。

还有个细节：`baseUrl: "."` 这行不能省。`paths` 里的 `src/*` 是相对 `baseUrl` 算的，少了它，看起来刚好也对，但那是巧合——恰好配置文件就在根目录。哪天挪一下位置就露馅了。

## 三、Element Plus 按需导入：unplugin 的两个插件

组件库就像一整个仓库的家具，全量引入等于把仓库整个搬回家，七百多 KB，实际你只用得上四十件。

按需导入的逻辑是：你用到哪件，才让人送哪件。实现这件事的是两个「自动跑腿」的插件。第一个负责看你的模板：你写了 `<el-button>`，它就悄悄在文件顶上补一行 import，把按钮和它的样式一起拿进来。第二个负责看你写的代码：你调了 `ElMessage`（一个弹消息的函数，不是组件），它也悄悄补上 import。

配好之后，模板里直接写标签就行，不用 import，也不用引那整包 CSS。省事是真的省事，但有个副作用：新人翻代码时会困惑——「这个按钮从哪冒出来的？项目里怎么搜不到 import？」所以一定要在 README 或主文件里写一句「组件库是自动导入的」，一句注释能省下后来人半小时。

最常见的失败是「配了但没生效」。九成原因是没重启开发服务器。这类工具是在启动时读配置的，你改完配置它不会自己重读，症状就是「明明写了却报 undefined」。删掉缓存目录重开一次，基本都能好。

## 四、主题定制：SCSS 变量覆盖的生效链路

小兔鲜的品牌色是橙色，组件库默认是蓝色。换色有两条路，像换招牌的两种办法。

第一种是**贴张膜**（CSS 变量）：招牌不用拆，在外面蒙一层橙色膜，五分钟搞定。优点是快、不用装额外工具；缺点是只能改颜色，改不了圆角、字体、间距这些「尺寸类」的东西。

第二种是**出厂前改配方**（SCSS 变量）：在油漆出厂时就把配方里的蓝改成橙，这样所有用这批漆刷的地方都是橙色，包括你没注意到的边角。代价是要装 Sass，还要改构建配置。

配方的原理不难理解：组件库的样式源码在最开头写了一句「我这批漆的颜色，默认是蓝」，你只要在自己家里先用同样的句式「声明这批漆是橙」，后面所有引用都会用你的橙。这叫「先声明，后使用」，所以覆盖文件必须放在最前面，而且在 Sass 里，这类声明语句要写在整个文件的最上方，中间夹了其他内容就会报错。

容器（Vite）那边还要加一句「所有样式文件开工前，先读一遍配方」。这条链路最容易断在三个地方：路径写错、配方被后来的配置覆盖、以及装了 Sass 没重启。判断方法很简单——看编译有没有报错，报错就是路径或语法问题，不报错但颜色没变就是缓存问题。

## 五、axios 封装：实例、拦截器与统一返回

不封装会怎样？每个请求都要写一遍服务器地址、塞一遍 token、弹一遍错误提示。一百个接口就是三百行重复代码，而且改一次地址要改一百处。

封装就像公司前台。所有快递（请求）都交给前台，前台负责三件事：寄件地址统一填（baseURL）、每件都盖上公章（带 token）、收件时先验货再转交（统一处理错误码）。你只需要跟前台说「帮我寄一份商品列表」，剩下的不用管。

做法分四步。第一步建一个「专用通道」，把服务器地址和超时定死。第二步挂上「出门前检查」：有 token 就自动带上，取 token 要在函数里面取，不能在文件最外层取——这一点第 2 章反复强调过。第三步挂上「收货时检查」：后端有个坏习惯，明明出错了也返回 200，真正的错误码藏在响应体的 `code` 里，所以必须自己看一眼。

第四步才是写具体接口，只负责「叫什么名字、传什么参数」，不做任何业务判断。这样将来换地址只动一处，改错误处理只动一处，页面里干干净净全是「调函数拿数据」。

这里有个决定必须全项目统一：前台交货时，给你整箱（`res`）还是只给你货（`res.data`）？如果给整箱，每个页面都要拆两层；如果只给货，页面里直接就能用。两种都行，但绝不能一半给整箱一半给货——那会是全项目最费时间的 bug，因为每处都要去翻源码确认。

## 六、路由整体设计：分层与懒加载

路由表就是商场的楼层导览图。写之前先想清楚三件事：哪些楼层共用同一部电梯（共享布局）、哪些店面要刷卡进（需要登录）、哪些是同一个店面换个房间号（参数不同复用组件）。

小兔鲜的导览图分两层。顶层是「大厅」：统一的顶部导航加一块内容区，首页、分类页、详情页、购物车都从这块内容区里长出来。另一支是独立的登录页和会员中心，它们不套大厅，整页自己排版。

每层楼都要「用到才装修」（懒加载）。如果一进门就把所有楼层的灯全打开，第一屏会白等很久。写成 `() => import()` 之后，首屏只加载大厅和首页，其他楼层等你要去的时候才下载。

三个容易写错的地方。第一，大厅里的默认子页面用空路径 `''` 表示，访问根地址时自动显示首页。第二，带参数的路径要放在后面，`/detail/create` 和 `/detail/:id` 同时存在时，谁写在前面谁先被匹配，写反了「create」就会被当成一个商品 id。第三，需要登录的页面不要每个页面自己检查，而是在「进门闸机」处统一判断（全局守卫），没卡就送去登录页，还要记住他原本想去哪——这就是 `redirect` 参数，不然用户登完回来还得重新点一遍。

## 七、静态资源与 SCSS 变量自动导入

图片放哪儿？有两个房间：自己厨房（`assets`）和门口储物柜（`public`）。

放厨房的东西会被加工：小图会揉进代码里（转 base64），大图会重命名加上一串指纹（hash），好处是换了图浏览器一定拿到新的。放储物柜的东西原样摆着，路径固定不变，适合 favicon 这种「必须固定地址」的文件。

判断标准就一句话：需要被代码引用、要参与打包的，放厨房；需要固定网址直接访问的，放储物柜。两者别互相串门，串了就会出现「开发时好好的，上线 404」，或者「换了图浏览器还显示旧的」。

另一件事是「变量自动带进每个文件」。你定义了一堆颜色变量，几十个组件都要用；如果每个文件都写一遍「去读那份变量表」，就是几十行重复。构建工具提供了「开工前先读一遍」的配置，每个样式文件编译前先把你指定的那行 `@use` 插进去。

这个配置项和第四节主题定制用的是同一个位置，所以两行 `@use` 必须写在一起，用换行隔开。如果写成两个配置项，后一个会把前一个顶掉，症状很典型：主题色换成功了，但自己的变量提示找不到。

## 八、工程实践与常见坑

**一、外号只告诉了一边。** 代码能跑但编辑器一片红线，或者反过来。邮局和门卫都要登记，配完还要让门卫重启一下记忆。

**二、自动导入没生效。** 提示 `ElMessage is not defined`，或者按钮没样式。八成是没重启开发服务器，清掉缓存再开一次。

**三、换了颜色没反应。** 三种可能：走的是「贴膜」的路却指望改尺寸；路径写错；配方声明没放在文件最前面。先看编译报不报错。

**四、交货方式一半一半。** 有的地方拿到整箱，有的地方只拿到货，于是页面里时而拆两层时而不拆。定死一种，全项目照做。

**五、所有楼层一起开灯。** 首屏加载特别慢、打包出来只有一个巨无霸文件。页面级组件要用「用到才加载」的写法。

**六、厨房和储物柜混用。** 上线后图片 404，或者换图不生效。按第七节的标准分清楚，别互相引用。

## 一句话总结

项目起步就是「先把水电门窗定好再进家具」：外号要跟邮局和门卫都说一遍，组件库只搬用得上的，换招牌要么贴膜要么改配方但别混着来，快递统一交给前台，楼层图先分层再决定哪层用到才开灯。
