# 一级分类页

> 这一章讲「同一个房间换了门牌号」：页面还是那一页，但门牌号（分类 ID）一变，里面的东西全得跟着换。

## 一、一级分类页的职责：一个 ID 撑起整页

一级分类页就像商场的一整层楼：门牌号是楼层号（分类 ID），进了门你会看到四样东西——「你在几楼」的导览牌（面包屑）、这块场地的活动海报（Banner）、通往别的楼层的电梯（分类导航）、以及这一层摆的商品（商品列表）。

四样东西都认同一个门牌号。门牌号换了，四样都得换。

所以这一页最重要的规矩是：**页面必须能对「门牌号变了」做出反应**。

新手常见的写法是「进门时把东西摆好」，只写一次。从外面进来时没问题。可如果顾客已经在楼里了，直接按电梯去另一层（在页面里点另一个分类），地址栏的数字变了，货架却一动不动。

这不是数据没取到，而是「进门时摆货」这件事根本没有再发生一次。原因和修法，第六节专门讲。

还有一件事要先想清楚：**要不要记住这一层的样子**。离开再回来，是希望你上次站的位置和看到的货都还在，还是希望重新拉一遍最新的？价格库存会变，所以电商列表通常是重新拉；但切换楼层时不能整页白一下。这两件事处理方式不一样，后面分开说。

## 二、静态结构与路由配置：先把占位组件跑通

装修的第一天不进家具，只钉几个空展位，确认门能进、路能走。

写页面也一样：先建一个只有标题的空组件，把路由配好，确认能从首页点进来，再往里填东西。

路由里那个 `:id` 就像「门牌号占位符」——位置固定，号码可变。链接必须把具体号码拼出来，写成 `/category/1005000`，而不是只写 `/category`。

这里有个细节：只写 `/category`（没号码）是进不去的，或者说「有这个门但没有房间」。所以首页那个「全部分类」的入口不能直接指向它，要么展开一个面板让用户选，要么给个默认楼层。不要留给用户一个「合法但空白」的页面。

空组件阶段先用假数据摆一摆：放 4 个、放 8 个、放 20 个都试一遍，看看空的时候、只有一行的时候、图片大小不一的时候会不会塌。等架子稳了再接真数据。

反过来先接接口，一旦页面难看，你就分不清是「货不对」还是「架子歪了」，排查时间翻倍。

## 三、面包屑导航：组件、接口与「能不能点」

面包屑就是商场里那块「你在这里」的导览牌，写着：一楼 / 二楼 / 手机数码。

它要处理三件事。

**第一，怎么写出一串层级。** 每层做一个小牌子的形状，外面套一个容器把它们连起来，中间自动插分隔符。这样加一层减一层都不用改样式。

**第二，哪一层能点。** 前面几层能点（点「首页」回首页），最后一层不能点——点它就是「跳到当前页」，没有意义。这个判断放在小牌子里面做：调用的人只要告诉它「有没有目标」，不用每次都写一遍判断。

**第三，数据从哪来。** 面包屑只要一个名字，但页面还要商品、筛选条件。不要为了「只要一个名字」单独打一次电话（发一个接口），直接用页面本来就要取的那份分类详情里拿出来用。

只有一种情况值得单独取：这一页东西特别多、加载慢，而导览牌一进门就得看见。那就先取个「轻」的版本把牌子挂上，主内容慢慢来。

最后一个边界：**有人拿了一个不存在的门牌号**。接口什么都给不出来，牌子上就会出现「首页 / 」这种半截话。这时候要补一句兜底文案，再给个「回首页」的出口，别让人困在空房间里。

## 四、分类 Banner：把首页的轮播抽成可复用组件

首页有一块广告屏，分类页也要一块——但放的内容不一样。

正确的做法不是「再买一块一模一样的屏」，而是**把这块屏做成能换片源的**。

小兔鲜的做法很巧：取广告图的接口多了一个「位置」参数，首页传 1，分类页传 2，后端按位置给不同的图。组件里把这个位置声明成一个参数，不传就用 1（首页），分类页写 2。

这样首页一个字都不用改，分类页多写一个参数就有了自己的广告。

重构时有两条纪律。

**第一，别把两处的差异全堆成参数。** 如果以后分类页要「三张图、不自动播」，首页要「五张、自动播」，那就不是在同一个组件里加开关，而是该考虑拆成两个——第 5 章说过的判断：差异小于两成就合并，差异会一直长就分开。

**第二，别在组件里猜高度。** 两个位置的图比例不一样，首页是宽幅、分类页更扁。高度应该由使用的地方传进来，而不是在组件里写「如果是分类页就用 300」。差异用参数表达，不要用如果表达。

## 五、导航激活状态与分类列表渲染

这一页里有两个「列表」，长得像，性质完全不同，别搞混。

**一个是电梯按钮**：所有一级分类的集合，作用是「让顾客去别的楼层」。这份数据外壳（Layout）早就取过了，这里不要再取一次。

**一个是货架**：当前这一层摆的商品，作用是「让顾客挑」。这份数据是这一页自己取的。

电梯按钮要「亮」——当前在哪个分类，哪个按钮亮。有两种判断方式：一种是交给链接自己判断（它认识地址），另一种是自己拿地址里的号码比一比。

区别在于：链接自己的判断比较「宽松」，`/category/1005000` 会让 `/category` 也亮起来；自己比则是严格相等。如果电梯里混着「全部分类」这种大按钮，就得用严格模式，否则大按钮和具体楼层会同时亮（第 4 章踩过这个坑）。

还有个现实问题：从二级楼层返回时，一级按钮常常不亮。因为地址里是二级分类的号码，两种判断都对不上。这时候得先找到「它属于哪个一级分类」再去点亮——这是信息架构的问题，不是改改样式能解决的。

货架这边有一个细节：给每一件货一个稳定的编号。如果用「第几件」当编号，换一批货时，页面会以为「第 0 件还是第 0 件」，只换内容不换位置，图片就会错位闪一下。

最后，**空货架也要有话说**。新开的分类没商品很正常，页面该显示「该分类暂无商品」并给个返回入口，而不是白茫茫一片让人以为坏了。

## 六、路由缓存问题：同一个组件、不同的 ID

这一节是整章最值钱的一段。

Vue Router 有一个「省事」的设定：**门牌号变了、但房间还是同一个房间时，它不会重新装修**。

也就是说，从 `/category/1005000` 点到 `/category/1005001`，组件不会先拆掉再建一个，而是留在原地，只把地址里的号码换掉。于是：

- 一进门做的那些事（`setup`、`onMounted`）不会再做
- 离开时的清理也不会做
- 只有「当前地址」这一个东西变了

表现出来就是：地址栏变了，页面不动。第一次遇到的人几乎都会去查「接口是不是没请求」，其实请求压根没发出去。

修法有三种，排序如下。

**第一种，盯着门牌号。** 号码一变就重新摆货。这是最推荐的做法，代码位置集中，读起来就是一句「号码变了要干什么」。

注意它通常带一个「立刻执行一次」的开关——因为第一次进门也得摆货。很多人忘了这点，进门时页面是空的；或者反过来，既写了「进门摆货」又写了「盯着号码」，结果一进门请求发了两次。

**第二种，换门牌就重新装修。** 给出口加一个「按完整地址区分」的开关，任何地址变化都重建。这招管用，但副作用大：整个外壳的状态都被清掉（菜单展开、滚动位置），动画重放，而且这个开关影响的是所有子页面，不只是分类页。范围太大，一般不划算。

**第三种，只在「同一房间换号码」时拦一下。** 语义最准，但它不管第一次进门，还得另外补一次，等于两处都要写。

选第一种的理由是「好读」：一个监听就把来龙去脉写在一处，也方便后面抽函数。

还有个衍生坑：**手速快的人连点两个分类**。先点的那个可能后回来，把后点的结果盖掉。处理办法是记个序号：只认最后一次，前面回来的直接丢掉。

## 七、基于业务逻辑的函数拆分

到这一步，页面里已经挤了三件事：取分类详情、取商品、处理号码变化。再往里写就要变成一个两百行的大文件了。

该拆。但拆的标准不是「代码太长」，而是「**它们变化的原因不一样**」。

分类详情跟着「是哪个分类」变；商品列表跟着「第几页、什么筛选」变。两个变化理由，就该是两块。

拆出来的两块各管一摊：一块负责「这个分类叫什么、有什么」，一块负责「这一页有哪些货」。页面组件只剩「把它们摆上去」。

有两个地方容易拆坏。

**第一，取当前地址这件事必须在「组件建立」的时候做**，不能放到按钮的回调里，否则拿不到当前的路由信息。

**第二，「盯着号码」这件事是跟组件绑在一起的**，组件消失时要自动停。这也是它不能随便拿到组件外面去用的原因——第 4 章讲的「作用域」就是这条规矩的底层解释。

最后一句判断：**别为了显得架构好而拆**。一个函数只被一处用、只干一件事、不到三十行，留在原地更好读。拆的好处是「能复用」和「把变化隔开」，两样都不成立时，拆只是把代码挪远了。

## 八、工程实践与常见坑

**一、点了另一个分类，页面不动。** 门牌号变了但没重新摆货。要盯着号码变化，并且第一次也要执行一次。

**二、接口请求了两次。** 既写了「进门摆货」，又写了「盯着号码」。二选一，通常只留后者。

**三、面包屑最后一层也能点。** 因为每一层都给了目标地址。最后一层不给，组件自己判断显示成普通文字。

**四、连点两个分类，数据显示串了。** 先发的晚回来覆盖了后发的。记序号，只认最后一次。

**五、分类页广告比例不对。** 沿用了首页写死的高度。高度和片源都由使用的地方传，组件不猜。

**六、列表用「第几件」当编号。** 换分类时图片错位闪一下。用数据自带的编号。

**七、空分类一片白。** 没写空态。补一句文案加一个返回入口。

## 一句话总结

一级分类页就是「一个门牌号撑起一整层」：先立空架子、再挂导览牌、再装可换片源的广告屏、再点亮电梯、最后摆货；门牌号变了必须重新摆货，不然页面会当着用户的面装死；把「跟着分类变」和「跟着分页变」的两件事拆开写，页面才不会越改越乱。
