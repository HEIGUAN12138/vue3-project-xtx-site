# 商品详情 · 练习与自测

## 一、是非题（10 题）

1. 商品详情页应该假设用户一定是从列表页点进来的。
2. `router.back()` 在用户从站外链接直接进入详情页时可能把用户带出站外。
3. 同一个详情组件、不同 `id` 时，组件会被复用，`onMounted` 不会再次执行。
4. 图片预览组件的当前索引在图片列表变化时应重置为 0。
5. 放大镜只需要修改 `background-position`，不需要改 `background-size`。
6. 放大镜的位置应该夹在容器范围内，否则会飘到图片外。
7. 每个商品只有一个价格，与 SKU 无关。
8. 「加入购物车」应该在规格选完后才可用。
9. 热榜的标题应该由接口返回，而不是前端写死。
10. 组件插件的 `install` 中适合放入「初始化用户信息」这类业务请求。

### 答案解析

1. **错**。入口有列表、热榜、搜索、站外链接，不能假设来源。
2. **对**。`history.state.back` 为空时 `back()` 会离开站点。
3. **对**。路由记录相同、仅参数变化时复用实例。
4. **对**。否则新商品图片更少时，索引越界导致大图空白。
5. **错**。只改位置是「平移」，必须同时放大背景尺寸。
6. **对**。需要 `Math.min(Math.max(...))` 夹紧。
7. **错**。价格绑在 SKU 上，同一商品不同组合价格可能不同。
8. **对**。未选完规格后端不知道发哪个货。
9. **对**。避免运营改文案就要发版。
10. **错**。插件只做注册，副作用应放在入口或独立初始化函数。

## 二、选择题（10 题）

1. 从「详情 A」点热榜里的「详情 B」页面没变，原因是？

   A. 直接 `router.back()`　B. 判断 `history.state.back` 后再决定　C. `location.href = '/'`　D. `window.close()`

3. 图片预览的「当前索引」应该在什么时候重置？
   A. 页面卸载时　B. 图片列表变化时　C. 每次点击大图时　D. 不需要重置

   A. `background-repeat`　B. `background-size`　C. `z-index`　D. `overflow`

   A. 打折前后　B. 不同 SKU 的价格区间　C. 运费区间　D. 接口错误

   A. 再维护一份选中状态　B. 只保存结果　C. 重新请求分类　D. 忽略

   A. 固定 99　B. 当前 SKU 的库存　C. 商品总数　D. 用户等级

   A. 渲染空 tab　B. 整块隐藏　C. 报错提示　D. 显示暂无数据并保留 tab

9. 把全局组件收进插件的直接好处是？
   A. 减少打包体积　B. 注册集中、主入口干净　C. 自动按需加载　D. 提升运行速度

10. 插件注册顺序上，通常应？
    A. 先自己的组件再组件库　B. 先组件库再自己的组件　C. 顺序无关　D. 只注册组件库

### 答案解析

1. **B**。同一路由记录参数变化复用实例。
2. **B**。有来源才后退，没有则回首页。
3. **B**。列表变短时索引会越界。
4. **B**。缺 `background-size` 就只有位移没有缩放。
5. **B**。不同组合价格不同，未选定时显示区间。
6. **B**。两份状态必然不同步。
7. **B**。库存绑在 SKU 上。
8. **B**。空榜单留着 tab 只会让用户误点。
9. **B**。体积与性能不受影响，收益在可维护性。
10. **B**。自己的组件可能依赖组件库，且重名时后注册覆盖前者。

## 四、情境分析（3 题）

### 情境 1：从热榜点另一个商品，页面毫无反应

用户在详情 A 的热榜里点了商品 B，地址栏从 `/detail/1` 变成 `/detail/2`，但主图、标题、价格全没变。

**问**：原因与修法。

**答**：路由记录相同、仅参数变化，组件被复用，`onMounted` 不再执行。修法：`watch(() => route.params.id, load, { immediate: true })`，并同时重置图片索引、选中规格、数量；或者给详情页的路由出口加与 `path` 绑定的 `key` 强制重建。

### 情境 2：换了商品，大图区域是空白

从商品 A（5 张图）跳到商品 B（2 张图），大图区域空白，点小图又能显示。

**问**：原因与修法。

**答**：`current` 索引还停留在 4，而 B 只有索引 0、1，`list[4]` 是 `undefined`。修法：`watch(() => props.list, () => { current.value = 0 })`，组件内部监听列表变化并重置。

### 情境 3：没选规格就加购，后端报错

用户直接在详情页点「加入购物车」，接口返回「缺少 skuId」。前端只在点击后弹了错误提示。

**问**：为什么这是设计问题而不是接口问题？

**答**：加购的前置条件是「规格已选完」，这个状态前端是知道的（`sku` 为空即未选完）。让用户点了才报错，等于把可预判的失败推给用户。正确做法是按钮 `:disabled="!sku"`，并在按钮旁提示「请选择规格」；库存为 0 时按钮直接显示「已售罄」。

## 五、代码阅读（3 题）

### 题 1

```js
onMounted(async () => {
  const { result } = await getDetailAPI(route.params.id)
  detail.value = result
})
```

**问**：这段代码在什么场景下失效？

**答**：在同一路由内切换 `id`（比如点热榜里的另一个商品）时失效。组件复用，`onMounted` 不再执行，页面仍显示上一个商品。

### 题 2

```js
const zoomStyle = computed(() => ({
  left: pos.x + 'px',
  top: pos.y + 'px',
  backgroundImage: `url(${list[current.value]})`,
  backgroundPosition: `-${pos.x * 2}px -${pos.y * 2}px`,
}))
```

**问**：这段样式有两个问题，分别是什么？

**答**：一是没有 `background-size`，放大镜里只是背景图平移，不是放大；二是 `pos.x`/`pos.y` 没有夹在容器范围内，放大镜会移出图片。

### 题 3

```js
export default {
  install(app) {
    app.component('XtxSku', XtxSku)
    app.component('XtxTabs', XtxTabs)
    getUserInfo()
  },
}
```

**问**：这段代码有什么隐患？

**答**：`install` 里混入了业务请求。只要引入这个插件（`app.use(UI)`）就会发请求，测试环境未登录会直接报错，而且很难定位来源。插件应只做注册，初始化逻辑放在 `main.js` 或独立函数里。

## 六、延伸思考（2 题）

1. 详情页之间，你会选 `watch` 重置还是 `key` 重建？请给出判断依据，并说明这个判断在「列表页」上是否成立。

   **思路**：详情页内部状态（当前图片、选中规格、数量）在换商品时全部应失效，没有保留价值，所以 `key` 重建可以接受，代码更省心。列表页不同：用户希望返回时保留滚动位置、已加载的分页数据，`key` 重建会把这些全部清掉，所以列表页应选 `watch` + 局部重置。判断依据可以概括为「组件内部有没有值得保留的状态」。

2. 「加购前必须选完规格」这条规则，放在按钮禁用、点击时校验、还是后端报错，三者各有什么代价？你会怎么组合？

   **思路**：只靠后端报错，用户点了才知道，体验最差且浪费一次请求；只在点击时校验，比后端好但仍有「无效点击」；按钮禁用最直观，但禁用状态本身可能让用户困惑「为什么点不了」，需要配合提示文案。合理组合是：按钮禁用 + 旁边写明「请选择规格」+ 后端仍然校验（防绕过）。前端负责体验，后端负责正确性，两者都不能省。
